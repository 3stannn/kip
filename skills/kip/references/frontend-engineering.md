# Frontend engineering

For React or Next.js implementation, refactoring, data fetching, bundle optimization, and performance review, read [Vercel's React best practices](../vendor/vercel-react-best-practices/SKILL.md). Load individual files from its `rules/` directory for the relevant code; the compiled `AGENTS.md` is an optional full reference, not instructions governing unrelated Kip files. Prioritize waterfalls and bundle costs before small optimizations. Apply rules supported by the project's installed framework version and architecture. Next.js-specific APIs do not apply to plain React apps. Preserve behavior, security boundaries, and the requested scope; bundling this guidance does not authorize migrations or unrelated dependency changes.

For component work in projects using shadcn/ui, projects with `components.json`, or explicit requests for shadcn components, read the bundled [shadcn skill](../vendor/shadcn/SKILL.md) and relevant linked rules. Prefer existing project components and semantic tokens. The vendored skill's shell-injection block is documentation when read as a file: it does not supply live project context. Inspect the actual target project using available tools and the project's package runner. Its host-specific frontmatter does not grant additional tools or permissions. Use available docs/CLI capabilities as appropriate, preserve local component changes, and preview updates before overwriting. Do not initialize shadcn, apply a preset, or replace another component system solely because the skill is bundled.

Use these engineering rules within the selected visual direction from [frontend-design.md](frontend-design.md). Existing component APIs, accessible fallbacks, and project icon configuration take precedence over generic stylistic suggestions from design skills. Give workers and reviewers only the relevant rules and actual project context; do not run every bundled skill's full workflow for a small change.

Pinned upstream revisions and licensing are recorded for [Vercel](../vendor/vercel-react-best-practices/SOURCE.md) and [shadcn](../vendor/shadcn/SOURCE.md). Normal Kip installation and updates copy all supporting resources offline.
